# Правила работы Codex с Git

Это краткие постоянные правила. SHA базового коммита, номер задачи и roadmap должны приходить из prompt, а не храниться здесь.

## Перед началом задачи

1. Всегда выполни:
   - `git status --short --branch`
   - `git rev-parse HEAD`
2. Проверь, настроен ли Git remote.
3. Новую функциональную задачу не продолжай от старой рабочей ветки.

### Если remote существует

- Определи default branch (`main`, `master` или default branch remote), выполни fetch и начинай новую задачу от её свежего состояния.
- Перед PR снова выполни fetch и убедись, что рабочая ветка не отстала от основной; при необходимости безопасно перенеси изменения на свежую основную ветку.
- При конфликте не создавай PR, не коммить конфликтные файлы и не оставляй conflict markers. Пересобери изменение от свежей основной ветки, если это безопаснее исправления устаревшей ветки.

### Если remote отсутствует в managed Codex environment

- Это не ошибка: не останавливай задачу только из-за отсутствия `origin`, не добавляй remote вручную и не запрашивай PAT или token.
- Используй предоставленные task snapshot и `HEAD`. Если prompt содержит expected base/merge SHA и commit доступен локально, проверь его наличие и ancestry относительно `HEAD`.
- Не требуй конкретного имени рабочей ветки: task branch и публикацией branch/PR может управлять платформа Codex. Оставь публикацию её штатному механизму.

## Безопасность и scope

- Не выполняй `reset --hard`, `clean`, destructive overwrite или force push без явной необходимости.
- Не перезаписывай свежие изменения основной ветки и не трогай unrelated files.
- Не создавай PR с конфликтами или незавершённым rebase.
- Перед PR проверь `git diff --check`, итоговый diff и отсутствие реальных conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`).
- Для изменений Python запускай targeted проверки затронутого кода; не запускай полный `pytest` без причины.

## Финальный отчёт

Кратко укажи: task `HEAD`/base, branch, наличие remote, изменённые файлы, выполненные проверки, наличие конфликтов и ссылку на PR.
