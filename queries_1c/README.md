# Запросы 1С

Каталог содержит только готовые запросы для ручного запуска в консоли запросов 1С.
Приложение читает файлы как текст: они не выполняются автоматически и не меняют импорт
Excel, парсеры, расчёты, маршрутизацию или остатки.

## Расходные ордера — расчёт количества коробов

Файл `mass_outbound_orders.query` выгружает товарные строки
`Документ.РасходныйОрдерСклад` и реконструирует расчёт количества коробов по логике
формы документа. Запрос проверен вручную: `РасчетноеОтгруженоКоробок` совпало с полем
«Отгружено коробок» в форме 1С. Исходные контрольные поля — количество из строки,
количество в коробке и результат контроля расчёта — сохраняются в выгрузке.
Фактическое поле `Документ.РасходныйОрдерСклад.Товары.ПорядокСборки` проходит через
обе временные таблицы отдельно от `НомерСтроки`. Итог сортируется по дате и номеру
ордера, затем по `ПорядокСборки` и только затем по `НомерСтроки`.

Перед выполнением задайте `ДатаНачала`, исключающую верхнюю границу `ДатаОкончания` и
`Склады` — список значений складов. Приложение запрос не выполняет: пользователь
копирует текст в консоль запросов 1С и запускает его вручную.

## Фактическое размещение — остатки по ячейкам в коробах

Файл `actual_inventory_by_cells.query` формирует текущий снимок фактических остатков;
период для него не задаётся. Единственный параметр `&Склады` принимает список складов.
Запрос проверен вручную в 1С. Товар связывается с физической ячейкой через паллету, а
количество коробов является реконструированным расчётом по нормативу для РЦ,
номенклатуры, характеристики и даты производства. Все исходные контрольные поля
сохраняются.

Строки без точного норматива не удаляются из выгрузки. При будущем импорте строка не
будет участвовать в симуляции, если `КоличествоВКоробке` отсутствует или равно 0 либо
`КонтрольРасчета` не равно «Расчет выполнен». При этом такая строка будет сохранена в
диагностике. Парсер и это правило импорта в текущем изменении ещё не реализованы.

## Инвентаризация склада — фактический остаток в коробах

Файл `inventory_results.query` — черновой запрос для ручной проверки в 1С. Источник
данных — `Документ.ИнвентаризацияСклад.Товары`; запрос выгружает все проведённые
документы за заданный период. Фактический остаток берётся из поля `Количество`, а
`КоличествоУчет` и `Расхождение` сохраняются для контроля. Количество коробов
рассчитывается по текущему нормативу на момент `&ДатаОкончания`.

Запрос пока не проверен на реальной выгрузке и намеренно не выбирает последний
документ по SKU. Нельзя автоматически складывать все документы периода или считать
более поздний документ полным остатком: документ может описывать частичный пересчёт.
После ручной проверки формата выгрузки будет создан отдельный Python-парсер.

Строки без найденной коробности не должны попадать в рабочий переходящий остаток,
но исходные строки при этом должны сохраняться в диагностике.

## Приходные ордера — дневной приход в коробах

Файл `day_receipts.query` — черновой запрос для ручной проверки в 1С. Источник
данных — `Документ.ПриходныйОрдерСклад.Товары`; запрос выгружает все проведённые
документы выбранных складов за заданный период. Дата начала включительна, дата
окончания исключительна.

Количество дневного прихода в коробах используется напрямую из поля
`КоличествоКоробок` без пересчёта через вес, штуки, норматив упаковки, количество
паллет или ВГХ. `КоличествоПаллет` сохраняется только для аудита.
`ПриемкаТерминаломЗакончена` сохраняется для последующей проверки, а
`ОжидаемыйПриход` сохраняется для аудита.

Запрос не ограничивает приход временем до 16:00, не группирует строки и не выбирает
последний документ по SKU. Одинаковые SKU могут встречаться несколько раз, потому что
каждая исходная строка приходного ордера остаётся отдельной строкой результата.

Запрос пока не проверен на реальной выгрузке. Python-парсер будет создан после ручной
проверки результата. Нулевые и некорректные строки пока не удаляются запросом; будущий
парсер должен сохранить их в диагностике.
